    Know your access

    Same tool, three ways to get there

    Paid Gemini access removes manual steps. It does not unlock the pattern. Ask IT which version matches your account, and check again each semester because Google changes these often.

    Gemini app only

    • Build in the Gemini app with Canvas
    • Clean the Sheet by hand with a check prompt
    • Copy Apps Script code into the Sheet yourself
    • Paste errors back into Gemini

    Data owner controlled sharing

    Three layers, one control point

    On the live path the tool runs as the person viewing it, so it can never show more than the Sheet allows.

    Layer 1, the control point

    The Google Sheet

    • Owner shares with named people or groups
    • General access stays Restricted
    • Viewers cannot download, print, or copy
    • Sensitive columns live on a separate tab
    Layer 2

    The tool

    • Apps Script web app attached to the Sheet
    • Execute as: User accessing the web app
    • Access: people in the district only
    • Never "Execute as me" for student data
    Layer 3

    The Google Site

    • Published to named people or the district
    • Never public on the web
    • A front door only. It grants no data access
    Remove a person from the Sheet and the tool shows them nothing.

    Let each group edit only its part

    Use this for course teams, grade level teams, administrators, and school teams that share one dashboard. All of it is set with Google Sheets sharing, with no extra tools.

    1. Give each dashboard section its own tab in the Sheet.
    2. Share the Sheet: people who only read get Viewer, people who add anything get Editor.
    3. On each tab choose Data, then Protect sheets and ranges, then Restrict who can edit this range.
    4. Pick the people or Google Groups allowed to edit that tab.
    5. In Share settings, turn off "Editors can change permissions and share."
    6. Deploy the tool to run as the user accessing it. It then follows those rules for every visitor.

    Continuity

    Build it so it outlives the builder

    A tool in one person's account disappears when that person changes roles or leaves. These five rules make every tool belong to the school.

    Rule 1The organization owns itEvery file lives in a shared drive, never in My Drive.
    Rule 2Roles get accessShare with Google Groups so access follows the job, not the person.
    Rule 3Two people can fix itAn owner and a backup, both managers of the shared drive.
    Rule 4The build is written downPrompts, code, and setup steps saved in a Build Notes Doc.
    Rule 5It is on the registerOne district list of every tool, its location, and its owner.
