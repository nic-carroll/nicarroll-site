# Gemini Tool Builder Playbook: Build It So It Outlives the Builder

> Part of the Gemini Tool Builder Playbook for K12 by Nic Carroll. For staff using Google Workspace for Education. Practical guidance, not legal advice. Your district privacy lead owns the final reading of FERPA and state law.

A tool in one person's account disappears when that person changes roles or leaves. These five rules make every tool belong to the school.

1. **The organization owns it.** Every file lives in a shared drive, never in My Drive.
2. **Roles get access.** Share with Google Groups so access follows the job, not the person.
3. **Two people can fix it.** An owner and a backup, both managers of the shared drive.
4. **The build is written down.** Prompts, code, and setup steps saved in a Build Notes Doc.
5. **It is on the register.** One district list of every tool, its location, and its owner.

## One Folder per Tool, in a Shared Drive

```text
Shared drive: Oakhaven HS Staff Tools
  Flex Scheduling Dashboard
    01 Data (Sheet, with the Apps Script attached)
    02 Intake Form
    03 Site
    04 Build Notes (prompts, code copy, settings)
    05 User Guide
    06 Archive
```

Gemini chats, Canvas builds, and Gems stay in the builder's own account. Copy the final prompts and code into Build Notes so nothing depends on one person's history.

## Handoff Checklist When the Owner Changes

- [ ] New owner and backup are named in the tool register
- [ ] New owner is a Manager on the shared drive
- [ ] Every file is in the shared drive folder, with nothing left in My Drive
- [ ] Build Notes are current, with the latest prompts and code
- [ ] The departing person walked the new owner through one change and one redeploy
- [ ] Sharing lists and tab protection are reviewed, and the departing person is removed
- [ ] The tool was opened as a regular user and works
- [ ] IT confirmed nothing depends on the departing account before closing it
